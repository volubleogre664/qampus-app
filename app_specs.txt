QAMPUS APP FEATURES SPECIFICATIONS
====================================

Registering and Logging In.
=============================

** Note: The token also contains data on how long a user must stay logged in. Which means a token expires and you need to login again for a new one **

1. Registering
 -> When creating an account, you just get a form to fill in information.
 -> The form on the app have minimal or HTML Default form validation.
 -> That info is sent to the server.
 -> Extensive Form validationis done on the server. Where we check the student numbers, passwords and names.
 -> We check for the password and confirm password, check for email, check if student number is valid and used and make sure no field is empty.
 -> Then throw an error if it is encoutered and returning the messages.
 -> If all goes well we create the user and return the user data and a token. A token is used in all SERVER_QUERYs to validate requests and everthing.
 -> The redirect to finaliseRegister page. Where we ask fpr final information to finalise the user info.
 -> The finialiseRegister page can be skipped without filling in the info.
 
2. Login
  -> A form with student number and password has to be filled
  -> The we validate the form in the server as we did in Register process.
  -> If all goes well, we validate the data based on the Database info. Check if student number exists in DB.
  -> If student number exists then, check if password is correct and if so we return the same info as on register.
  -> We return the user data with token
  -> Then redirect the user to the home page or any page they were visiting before logging in.

Chats and Book buying
======================

** Note: Whenever the chats page opens, the app subscribes to incoming messages, this enables realtime chatting. **

1. Buying book from Home Search Results.
  -> The book is first saved in the app state.
  -> Then the book's ID is passed through the URL.
  -> When Chats Page open, we first check the URL if there is a book ID passed through it.
  -> If the book ID is in the URL, we use the ID to get the book from app state.
  -> With the book from app state we get the bookOwner's student Number and make SERVER_QUERY for user data or bookOwner data.
  -> With The user data we make a contact in the chats and open up the chats.
  -> Then we will send the Book and a message saying "Hy {user.name} I would like to buy this book.
  
2. Opening Chats Anytime
  -> This works if chats are open and there is no book ID in the URL.
  -> We check for a list of contacts (will be saved in localStorage). Then load the contacts in the app state.
  -> Then cross check contacts with the data in Database using a SERVER_QUERY. If it is not consistent, the SERVER_QUERY returns correct contacts.
  -> Then the focus will be on the first contact on the list.
  -> When we focus on a contact, a SERVER_QUERY is made to get the messages between the you and that contact. The SERVER_QUERY takes 3 arguments.
  -> The SERVER_QUERY args are to, from, messagesLength. to and from args makee sure we get data between you(to/from) and the contact(to/from).
  -> The messagesLength arg makes sure that the SERVER_QUERY returns only the messages the app does not have.
  -> So if the app has 3 messages and Database has 7 messages, the SERVER_QUERY will send messagesLength of 3 and return only 4 messages.
  -> If they're equal it will return 0 messages.
  
3. Sending a message.
  -> When sending a messages, the SERVER_QUERY is passed with to and from and textMsg.
  -> to: reciever's student number. from: sender's student Number. textMsg: sender's message.
  -> As the Note: line in the start says, we make subscriptions to incoming messages.
  -> Each subscription on the app contains a student number. The student number is to make sure everyone receives the messages intended for them.
  -> So in the server, we will push a message to a subscription and pass the student number to it.
  -> Example: If 10 people have open subscriptions,  only one will receive the message because of the student number I passed to it.
